# Intermediate Representation

The first native lifted IR is implemented under `include/binobf/ir` as a typed, control-flow-aware representation organized as function, basic block, and instruction. The separate VM-independent execution IR remains under `include/binobf/vm`.

The canonical model includes explicit function signatures and ABI bindings; integer, pointer, floating-point, and vector types; typed constants and variables; register, argument, stack, local, global, and thread-local storage; addresses, loads, stores, pointer offsets, and casts; internal, declared external, and tail calls; direct, conditional, switch, and proven-target indirect control flow; returns; fallback effects; and nested cleanup/catch unwind plans. Void returns and internal calls omit their value/destination, while non-void forms require one of the exact declared type. These records are validated and preserved even where later architecture tracks have not yet implemented lowering or emission.

The IR is not intended to be a perfect decompiler. A native instruction that cannot be lifted safely remains a fallback operation with lineage to its original address and bytes plus complete conservative read, write, memory, clobber, control-flow, and unwind effects. A pass checks the exact proposed rewrite region and fails with `ir.fallback_blocks_transform` when it would cross that boundary.

IR blocks retain stable source block IDs and every operation retains its source instruction ID and bytes where a fallback is necessary. VM lowering emits an instruction-index-to-source lineage table. Function validation checks bounded canonical types and storage, variable and flag definition, pointer-width address arithmetic, program-point readonly provenance with conservative control-flow merges, memory/atomic rules, address-width indirect targets, all terminators and proven targets, complete fallback effects, and acyclic/exclusive unwind regions. Module validation additionally checks unique functions and external declarations, entry presence, exact call signatures and ABI bindings, legal tail calls, acyclic internal calls, and maximum call depth. Nodes outside the current VM subset fail as `vm.unsupported_native_ir` with node and source lineage; they are never silently skipped or reinterpreted.

`flatten_control_flow` converts a fallback-free function to seeded dispatcher form with unique 32-bit states. A mathematically fixed false edge leads to one valid, side-effect-free bogus block and then returns to the dispatcher; no external or environmental predicate is used. `outline_block` extracts only a safe non-entry block ending in a return, computes its live-ins, remaps them to helper arguments, and replaces the block with a real internal call. `split_function` moves the original body into a helper and leaves an ABI-facing call/return wrapper. All transformations validate their results and fail closed when their preconditions are not proven.

Status: selected x86-64 `u32` register/immediate arithmetic and control-flow lifting is **restricted but supported** for complete COFF/ELF object functions. VM lowering, module lowering, advanced standalone control-flow transformations, validation, assembly, decoding, disassembly, interpretation, and selected-function embedding are **supported**. General lifting remains **planned**.

The supported i386 object backend does not claim general native-to-IR or VM lowering. It recovers complete functions/CFG/liveness and applies backend-owned byte/fixup/layout templates transactionally; unsupported semantics stay opaque and block only the affected rewrite. Expanding i386 native lifting remains a separate later milestone.
